# Імпорт заявок з .xlsx

Сторінка завантажує файл `.xlsx` і записує всі його рядки в таблицю `leads` (MySQL) при стандартному `max_execution_time = 30`. Структура БД лежить у `schema.sql`.

```
public/                  корінь сайту
  index.html             розмітка
  css/styles.css         стилі сторінки
  js/app.js              обробка форми й повідомлення про результат
  js/api.js              виклик API з браузера
  api/import.php         POST файлу -> {"imported": N, "duplicates": N} або {"error": "..."}
src/
  Importer.php           читає файл і записує нові рядки однією транзакцією
  Database.php           уся робота з БД: підключення з env, транзакції, пакетні вставки
  SheetReader.php        потокове читання аркуша xlsx (XMLReader)
  ExcelParser.php        відповідність колонок за заголовком, розбір і перевірка значень Excel
schema.sql               структура БД
```

## Запуск

```bash
cp .env.example .env           # вписати паролі DB_PASS і MYSQL_ROOT_PASSWORD
docker compose up -d --build   # http://localhost:8080, MySQL: 127.0.0.1:3307
```

Паролі зберігаються лише в `.env`, який не потрапляє в репозиторій (`.gitignore`). Застосунок підключається до БД окремим користувачем `DB_USER` з доступом тільки до бази `DB_NAME`, а не під root.

Без Docker потрібен PHP 8.1+ з `pdo_mysql`, `zip`, `xmlreader`, `dom` і `mbstring`. Далі:
- виконати `composer install --no-dev`;
- спрямувати корінь сайту на `public/`;
- імпортувати `schema.sql`;
- задати `DB_DSN`, `DB_USER` і `DB_PASS`;
- підняти `upload_max_filesize` і `post_max_size` щонайменше до 32M (ліміт файлу 30 MB, наданий файл важить ~11 MB).

## Як імпорт вкладається в 30 секунд

- **Файл не завантажується в пам'ять цілком.** PhpSpreadsheet на 100 тис. рядків × 15 колонок не вклався б ні в час, ні в пам'ять. `SheetReader` читає аркуш рядок за рядком через `XMLReader`, прямо з архіву. Аркуш він знаходить через `workbook.xml`, тож працюють префікси тегів, будь-який порядок атрибутів і будь-яка назва файлу аркуша.
- **Рядки вставляються пачками по 1000** в одній транзакції: файл імпортується або повністю, або ніяк.

Результат: 100 000 рядків приблизно за 3.5 с, пікове споживання пам'яті 20 MB.

## Правила для даних

Мають записатися всі рядки, тому жоден рядок не відкидається. У колонках лежать лише чисті значення:
- **Некоректне значення:** колонка стає NULL, а оригінальний текст зберігається в `leads.invalid` (JSON), наприклад `{"phone": "12345", "email": "a@@b"}`. Нічого не втрачається.
- **Задовгий текст:** обрізається під розмір колонки, а повне значення теж іде в `invalid`. Тому вставка не може впасти на `STRICT_TRANS_TABLES`.
- **Телефон:** приводиться до `+380XXXXXXXXX`. Розпізнаються:
  - числа з Excel (`380671234567`, `380671234567.0`, `3.80671234567E+11`);
  - запис `+38 (067) 123-45-67`;
  - текст `0671234567`, який не втрачає нуль на початку.

  Некоректними вважаються:
  - номери з літерами, із замалою кількістю цифр або з кодом `00`;
  - експоненційний запис, у якому втрачено цифри: `3.8E+11` не стає `+380000000000`. Excel у такому записі відкидає й нулі в кінці, тому `3.8067123456E+11` теж не приймається, хоча це може бути номер `380671234560`.
- **Дати:** приймаються серійні дати Excel (`45848.213125`) і рядки у форматах `2025-07-10 05:06:54`, `2025-07-10 05:06`, `2025-07-10`, `2025-07-10T05:06:54`, `10.07.2025 05:06:54`, `10.07.2025 05:06`, `10.07.2025`. Час береться як є, без зсуву на часовий пояс сервера. Некоректні: будь-який інший текст (`tomorrow`), дата, якої не існує (`31.02.2025`), рік поза 2000–2100.
- **Бюджет:** `1 500,50` читається як 1500.50. Значення, що не є числом або не вміщається в `DECIMAL(12,2)`, іде в `invalid`.
- **Дублікати:** лід визначається парою `external_id` + `created_at` (UNIQUE-ключ). Лід, який уже є в базі, пропускається, тому повторне завантаження того самого файлу, навіть пересохраненого, нічого не додає. Самого `external_id` недостатньо: у файлі 205 id повторюються з різними даними та різним `created_at`, і всі ці рядки зберігаються.

У наданому файлі: 813 некоректних телефонів (`#ERROR!`-формули, `12345`, `380`) і 822 некоректні email.

## Обмеження

- **Файл більший за 30 MB не приймається.** Сторінка повідомляє про це одразу, ще до відправки, а сервер перевіряє розмір ще раз.
- **Імпортується лише перший аркуш книги.**
- **Увесь імпорт виконується одним запитом.** Файл на 28 MB (325 тис. рядків) імпортується приблизно за 10 с, тож ліміт у 30 MB вміщається в 30 секунд із запасом.
- **Рядок із порожнім `external_id` або `created_at` захистом від дублікатів не покривається.** MySQL не вважає NULL однаковими в UNIQUE-ключі, тож такий рядок додається знову при кожному повторному імпорті.
